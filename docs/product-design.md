# 产品设计

## 1. 定位

Arbor 是 **人设工作台**，不是更会聊天的对话框。

聊天是入口。产品本体是：人设档案、分层记忆、事件树、租户权限。陪伴助手与数字员工共用内核，首页用模板皮肤区分。

一句话：

> 创建人 → 喂经历 → 对话 → 看见树在长 → 能检查他记得对不对、有没有串人、有没有漏到别的租户。

## 2. 核心对象

用户只需要理解四件事：

| 对象 | 用户语言 | 规则 |
|---|---|---|
| 工作空间 | 我的团队 / 我的私人空间 | 租户硬隔离 |
| 数字人 | 林夏、客服小周 | 一个会话只跟一个人设说话 |
| 记忆 | 档案、导入的资料、聊过的事 | 可见、可确认、可追溯 |
| 事件树 | 这个人的经历目录 | 关键事件是主干，日常是折叠的枝 |

## 3. 信息架构（页面）

三个主页面，外加两个轻量流程。

### 3.1 工作空间首页

卡片墙。每张卡片：头像、一句话身份、记忆条数、上次互动、皮肤标签（陪伴 / 员工）。

操作：创建数字人、从模板创建、从聊天记录导入生成初稿。

### 3.2 工作台（核心，三栏）

**左栏 · 资产**

- 身份档案（结构化，可直接编辑，保存后立即生效）
- 关系
- 知识库（文本、PDF、图片、语音）
- 工具权限（日历、工单等，人设级）
- 谁能用这个人（`chat` / `read_memory` / `write_memory` / `admin`）

**中栏 · 对话**

- 文字 / 图片 / 语音 / 文件
- 回复下方展开「依据了哪些 MemoryItem、哪个 EventNode」
- 新事实与旧档案冲突时，进入收件箱而不是静默覆盖

**右栏 · 生命线**

- 默认：关键事件树（可折叠）
- 可切换：时间轴
- 两种视图同一数据源
- 节点可打开事件卡：时间、人物、因果、原话、附件、置信度

### 3.3 记忆体检

评测的产品入口，不是隐藏的脚本。操作手册与金标见 [evaluation.md](evaluation.md)，夹具在 `eval/fixtures/suite-v1/`。

演示模式（面试默认）：

- 体检页 **「演示模式（装载 + suite-v1）」**：一键装载冻结世界并跑 `layered_tree` 检索
- **「加载最近四策略」**：读 `eval_runs` 中最近 suite-v1 检索记录，免重复现场跑
- 默认跑检索模式，现场不调 DeepSeek
- 逐题红绿：期望行为、命中的记忆 ID、来源层
- 顶栏：身份一致、Recall@5、人设泄漏、跨租户泄漏（必须为 0）
- 可展开四策略对比表

用户自己的人设：v1 可以不做自动出题，避免用私域数据冒充金标。

### 3.4 记忆收件箱

DeepSeek 抽取出的候选事实、事件、冲突，一律进入 Inbox：

- 记下来
- 忽略
- 标成关键事件

陪伴向：人设不会擅自改自己。员工向：主管审批知识沉淀。

### 3.5 创建人设（首页）

v1 为 **单页创建面板**（`CreatePersonaPane`），不是独立多步向导：

1. 选模板或空白档案，填写名称与一句话身份
2. 可选：附带聊天记录 / 文档文件，创建后走 Inbox bootstrap
3. 模板：伴侣、导师、客服、面试官（与 §3.5 原「三步」语义等价，UI 合并为一屏）

完整导入向导仍在工作台「授权与导入」侧栏。

## 4. 两条路径，同一引擎

| | 陪伴 | 数字员工 |
|---|---|---|
| 人设例子 | 林夏 | 客服小周 |
| 导入 | 旧聊天、照片 | 手册、工单 |
| 事件含义 | 见面、约定、冲突 | 升级、承诺、结案 |
| 默认授权 | 创建者全开 | 一线 `chat`，主管 `read_memory`，运营 `write_memory` |

禁止做成两个应用。禁止角色广场、直播、虚拟偶像作为第一版形态。

## 5. 权限（产品层）

多租户要做，但不是权限中台。

**空间角色（3）**

- Owner：成员、删除空间
- Admin：创建人设、知识库、审计
- Member：仅能使用被授权的人设

**人设能力（4）**

- `chat`：对话
- `read_memory`：看档案与事件树
- `write_memory`：导入、确认 Inbox
- `admin`：改人设、删记忆、配工具

没有 `read_memory` 的记忆 **不得进入模型上下文**。前端隐藏不够。

审计：改人设、导入文件、导出对话、确认记忆，各记一条。

第一版不做：跨租户分享、人设市场、SSO/SCIM、字段级权限、集团组织树。

## 6. 记忆如何被用户感知

```text
导入或对话
  → 抽取（事实 / 事件 / 情绪 / 承诺）
  → 进 Inbox（冲突则标出）
  → 用户确认
  → 写入档案或事件节点或向量切片
  → 对话时按 档案 > 近期摘要 > 相关事件 > RAG 片段 组装
```

用户可见的对应物：档案多一条、树上多一个节点、回复下有引用。

## 7. 事件树的产品形态

不要做成技术味的图数据库可视化。做成人物传记目录：

- 纵轴时间主干
- 大节点：认识、入职、约定、冲突、里程碑
- 小节点默认折叠
- 颜色表示结果类型（承诺 / 冲突 / 里程碑）
- 过滤：只看关键事件 / 全部 / 按人物

背后可以是图，面上是可折叠目录。

## 8. 非目标（v1）

- 角色扮演广场、虚拟形象驱动交互
- 纯知识库问答产品
- GraphRAG / 独立 TreeRAG 框架
- 图搜图、音搜音
- 自训主模型
- Kubernetes、微服务拆分
- 企业权限平台

## 9. 成功标准（产品）

演示应能在 5 分钟内完成：

1. 导入一段旧聊天
2. 右侧出现若干事件节点
3. 提问「我们上次为什么吵架」，回答能点回该节点
4. 换一个人设问同一句，系统拒绝或表现为无知
5. 体检页跨租户泄漏为 0
