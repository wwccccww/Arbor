口径： 数字员工工作台。客服、导师、面试官等人设共用同一内核。禁止写陪伴、虚拟角色、消费向人设产品。

评测夹具里的样本人设（如「林夏」）只用于隔离 / Recall 金标，面试若被问到：那是评测夹具，产品形态是数字员工。

一句话

Arbor：面向团队的数字员工工作台。每人设独立档案、记忆与事件树；对话和资料沉淀为可导航经历，检索限制在租户与人设边界内，回答可追溯到记忆与事件节点。

技能栏

语言 / 后端： Java（主栈按真实项目写）、Python（本项目）
架构： DDD、六边形架构、多租户、RBAC
数据： PostgreSQL、pgvector、Redis、S3
AI 应用： RAG 检索编排、Function Calling、上下文编译、评测金标
工程： OpenAPI、数据库迁移、GitHub Actions、契约测试 / 架构测试

不要把 LangChain、GraphRAG、微服务、K8s 写进本项目技能。

项目条目（直接粘）

Python / FastAPI / PostgreSQL+pgvector / Redis / DeepSeek / bge-m3

设计并实现数字员工工作台后端：客服、导师、面试官等人设共用同一套内核。记忆分为结构化档案、会话摘要、事件树、租户内向量检索四层；对话回复必须引用本轮实际注入的记忆 ID。默认策略 layered_tree 在 477 题金标上 Recall@5 ≈ 0.92、身份一致 1.0、跨租户泄漏 0（纯向量为 0.70 / 0.63）。

  1. 领域建模与分层： 按 Identity / Persona / Memory / Event Graph / Conversation 拆限界上下文；领域层零框架依赖，应用层编排用例，HTTP 只做入站适配。用架构测试锁死 import 方向（对标 Java ArchUnit）。
  2. 多租户与授权： 空间三角色 + 人设四权（对话 / 读记忆 / 写记忆 / 管理）；无读记忆权限的内容不得进入模型上下文。查询强制 tenant_id + persona_id，Postgres RLS 作第二道门；跨租户命中视为 P0。
  3. 检索编排： 档案规则注入 → 事件图种子 + 因果/时序边 1～2 跳 → 全局 ANN 与 scoped ANN 做 RRF → lexical hybrid → MMR 去重；复合问拆子 query。上下文按 token 预算裁剪，幻觉 citation 丢弃。
  4. 写入闭环： 手册、工单、文档、语音经 Redis 队列异步解析；LLM 抽取进 Inbox，由主管确认后才写入知识或事件节点，冲突不静默覆盖档案。
  5. 质量与评测： 领域/应用单测用 Fake 端口；Postgres 契约测隔离；PR CI 跑无 LLM 检索金标；夜间跑生成质量 + RAGAS（只评本轮注入文本的忠实度）。四策略对比表证明「档案 + 事件树」优于纯向量。

投 Java 后端：1、2、5 在前。投 AI 应用：3、4、5 在前，1 留一句证明不是调包。

数字口径

规模集 suite-ragas-v1，477 题，夹具哈希嵌入（PR CI）；真 bge-m3 走 nightly。477 题是约 33 条源记忆上的问法扩张，用来比策略，不是工业级语料库。

口述

Java 后端：
这是数字员工的记忆与权限后端，不是聊天套壳。按 DDD 把人设、知识、事件图拆成聚合；授权和「冲突不能自动改档案」写在领域层。LLM、向量库、对象存储都是端口。用 Spring Boot 重做时，Controller 和 JPA 落在适配器层，领域包保持纯 Java。隔离是查询必带租户 + RLS，CI 里跨租户契约测试失败不能合入。

AI 应用：
数字员工的身份走结构化档案，不靠把设定塞进 prompt。检索强制租户过滤：档案规则注入、事件图路由、向量细节分层。默认策略相对纯向量，Recall 从 0.70 到 0.92，关键事件命中到 1.0，跨租户泄漏保持 0。评测有版本化金标和对比表；引用必须是本轮真正注入的记忆 ID。
