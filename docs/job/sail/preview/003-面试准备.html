P1-B1 痛点与分层

原文
团队要同时使用客服、导师、面试官等数字员工时，知识容易串、回答说不清依据。将档案、近期摘要、经历目录和细节检索分开处理，回复只引用本轮真正提供给模型的材料。

30 秒

如果把人设和资料一起丢进向量库，相似文本会把别人的知识召回来，回答也无法点回依据。所以身份用结构化档案每次必带，近期用摘要，经历用目录路由，只有细节走检索。模型引用必须是这轮塞进去的材料。

追问
- 为什么不只做 RAG？
- 这算 Agent 还是工作流？
- 档案改了为什么不重建向量？

证据 ✅ 仓库分层记忆与引用校验。
不能说 生产上已服务多少团队。
二三层 被问 GraphRAG：经历目录只扩一两跳服务因果问句，不做社区检测。

P1-B2 隔离与权限

原文
隔离做成后端规则：一线可以对话，主管才能改知识；没有读权限时，知识不会进入模型上下文。查询过滤与数据库行级策略同时生效，隔离用例失败则不能合并。

30 秒

数字员工进团队，权限不能靠前端藏按钮。一线只能聊，主管才能改知识。没读权限时，模型上下文里不会出现知识细节。查询带工作空间和数字员工边界，数据库还有行级策略。隔离测试失败不能合代码。

追问
- 前端隐藏不够吗？
- 向量库为什么和业务库放一起？
- 行级策略关掉会怎样？

证据 ✅ 领域授权、契约测试、评测禁读集。
不能说 已通过安全审计/等保。
二三层 模型胡编一个别的员工的记忆编号：不在本轮注入集合就丢弃。

P1-B3 检索与裁窗

原文
身份走结构化档案；因果类问题先定位经历再扩展相关节点；细节用向量检索与关键词检索融合。窗口不够时按相关度裁剪，模型给出的依据编号若不在本轮材料中则丢弃。

30 秒

「上次为什么升级」这类题，纯向量容易只命中表面相似句。先命中经历节点，沿时间或因果扩一两跳，再在相关范围内检索细节，并和关键词检索融合。窗口不够先丢掉低相关片段。

追问
- 召回变差怎么查？（美团一面凉点）
- 为什么还要关键词，不用纯向量？
- 扩跳会不会把无关经历带进来？

证据 ✅ 有对比策略和检索元数据。排查顺序：先看有没有漏过滤 → 档案题是否根本没走向量 → 经历是否没命中 → 再看融合与裁窗。
不能说 线上 Hit Rate / NDCG。
二三层 复合问拆成子问题；没有密钥时用规则拆，不假装每次都 LLM 规划。

P1-B4 待确认写入与工具

原文
手册、工单、文档和语音异步解析后进入待确认队列，主管确认才写入；与旧设定冲突时标出，不静默覆盖。数字员工按白名单查询日历、登记工单。

30 秒

模型抽取不等于事实。解析走队列，候选进待确认，人点了才落知识。冲突标出来。工具按这个数字员工允许的列表执行，例如查日历、登记工单，不是全局开放。

追问
- 工具调用失败怎么办？（美团一面凉点）
- 为什么不让模型直接改档案？
- 日历没授权会怎样？

证据 ⚠️ 工具失败路径是：不在白名单不执行；外部日历/工单依赖配置，失败应返回错误而不是假装成功。没有完整的指数退避生产方案，不要编。
不能说 已对接飞书生产租户、工单已上线业务。
二三层 写操作必须人确认；查日程相对只读。

P1-B5 评测数字与口径

原文
用冻结题集对比多种检索策略。……0.63 到 1.0……0.70 到约 0.92……泄漏为 0。……夹具嵌入，不是生产流量。

30 秒

我把测试和评测分开。测试保证不串租户、没权限的知识不进模型。评测在同一批冻结记忆上对比策略。分层相对只靠向量，身份题稳住，召回大约从 0.70 到 0.92，跨空间泄漏是 0。这些题是问法扩张，合入用的是确定性嵌入，不是拿线上模型刷分。

追问
- 477 题是大规模语料吗？
- 为什么身份一致能到 1.0？
- RAGAS 是不是证明隔离？

证据 ✅ 基线文件。身份题靠档案层，不靠向量。生成忠实度只看本轮注入文本，隔离靠过滤测试。
不能说 SOTA、刷榜、生产 AB。
二三层 真中文嵌入走夜间任务，和夹具表分轨，不混读。

E1-B1 门户对接海豚调度

原文
做门户到海豚调度器的登录跳转：管理员取得会话后，用户不存在则创建，项目存在则授权，项目不存在则失败返回。创建项目时检查并创建同名租户……

30 秒

业务同学从门户进调度系统，不能每人自己开账号。接口用管理员会话：没有用户就建，有项目就授权，没项目就明确失败。建项目时先保证同名租户存在，避免调度里人和项目对不齐。

追问
- 租户、用户、项目三者关系？
- session 失效怎么办？
- 这是你设计的还是按文档实现的？

证据 ⚠️ 流程来自用户原始笔记，公司/是否独立设计待补。能讲步骤，不讲成架构负责人。
不能说 我设计了海豚调度器插件体系。用户只写「熟悉如何自定义插件与源」，熟悉 ≠ 实现过，被问到说看过/了解，没落地就停。
二三层 和 Agent 的关系：接内部系统时先把身份和授权做成确定性接口，再考虑让模型去调。

E1-B2 采集与日志

原文
按通道配置……SeaTunnel……封装调度日志查询……

30 秒

采集通道的配置在库里。接口读配置，用 SeaTunnel 把上游表同步到下游。另做查调度日志的接口，任务失败时能看到跑到哪一步。

追问
- 同步失败怎么补偿？
- 为什么用 SeaTunnel？
- 日志接口权限？

证据 ⚠️ 实现过取配置和同步、查日志。没有用户提供的失败补偿方案，不要编 exactly-once。
不能说 我负责整条数仓。

E1-B3 用户、导出、通报、SQL

原文
封装用户新增与详情、导出表格、达到条件触发通报、低代码执行 SQL。

30 秒

这些是中台里的业务接口：用户增查、把查询结果导出表格、条件满足就通报、低代码页把 SQL 交到底层执行。

追问
- 通报会不会误发？原始笔记叫「短信炸弹提示」是什么？
- 执行 SQL 怎么防注入、防删库？
- Excel 导出量很大怎么办？

证据 ⚠️ 「短信炸弹提示」按内部告警/通报讲，不要用攻击性表述。SQL 执行的防护如果不是你做的，就说接口是按平台约定转发，安全策略以平台为准，不装做过完整 SQL 网关。
不能说 我做了短信轰炸工具。
二三层 副作用接口（通报、执行 SQL）更要权限和审计；这和 Agent 工具分级是同一类问题。

E1-B4 接口测试缺陷

原文
字段问题 2、返回缺数据 3、接口问题 1、文档缺前置流程 1。

30 秒

联调时按文档和实际响应对过，记了四类问题：字段不对、返回少数据、接口行为不对、文档没写前置步骤，反馈给对接同学。

追问
- 怎么发现的？有没有自动化？
- 这些问题后来修了吗？

证据 ✅ 数字来自用户原始记录。修没修、是否自动化待补，不知道就说当时记录并反馈了。
不能说 我搭建了测试平台、缺陷率下降百分之几。

通用自我介绍（45 秒口语版）

我是 Sail，想做 AI Agent 应用。实习在数据中台做 Java 开发，主要是把门户和海豚调度器打通，以及采集和一些业务接口。另外做了开源项目 Arbor：数字员工工作台。要解决的是多人共用时知识串线、回答没有依据。我把档案、摘要、经历和细节检索分开，工具按白名单调，知识要人确认才写入，并用冻结题集对比检索策略。我想投这个方向，是因为岗位要的记忆、上下文、工具和评测，我已经在一个可演示项目里完整走过。

若学校/公司已补，把第一句改成「我是 Sail，某校某专业，在某某公司实习」。

关键字卡

  • Java 实习：门户 → 调度器（用户/租户/项目授权），SeaTunnel 采集
  • Arbor：数字员工，知识不串、回答可指回
  • 分层：档案 / 摘要 / 经历 / 细节
  • 工具白名单 + 待确认写入
  • 评测：召回对比，泄漏为 0，数字非生产
  • 想做：记忆、上下文、接业务系统

项目逐字稿 · Arbor（90 秒）

模块 该怎么讲
背景 客服、导师、面试官等数字员工要进同一个团队产品。纯聊天或纯向量会串知识和说不清依据。
我做了什么 可演示工作台：对话、知识导入、待确认、经历目录、评测页。
分步 档案每次必带；经历目录回答因果类问题；细节检索；引用必须来自本轮材料；导入异步解析后等人确认。
结果 自建金标上，分层相对只靠向量，身份题稳住，召回大约 0.70 到 0.92，跨空间泄漏 0。
困难 难在「什么能进模型」和「什么算串线」，不是调一个向量接口。
下次 工具失败的重试和可观测还偏演示；真嵌入与夹具评测要继续分轨看。

项目逐字稿 · 实习（45 秒）

模块 该怎么讲
背景 业务同学要从统一门户用海豚调度器，不能自己去调度器开一堆账号。
我做了什么 Java 接口：登录跳转时建用户、给项目授权；建项目时补租户；采集走 SeaTunnel；查日志；用户、导出、通报、执行 SQL。
结果 联调里记了文档和字段、缺数、接口、前置流程共若干问题并反馈。
边界 我实现这些接口。中台整体架构、插件体系若只是熟悉，不说成我做的。

不会就不会

被问到 安全回答
为什么不用 LangChain？ 我了解它适合快速拼链路。Arbor 要把隔离和记忆规则做成可单测的领域逻辑，所以编排写在应用层。没有把框架当业务模型，也没有生产级 LangGraph 经验。
MCP / A2A / 多智能体怎么做？ 没做过落地。工具目前是人设白名单加日历、工单适配。协议层我可以学，但不能说已经实现。
工具调用失败怎么做生产级重试？ 演示里失败会返回错误、不在白名单不执行。指数退避、幂等键、补偿事务我没有在该项目里做成完整方案，这是我知道的缺口。
线上召回怎么监控？ 我有离线冻结题集和检索元数据，没有线上 A/B。排查会先看过滤、再看是否走错层、再看融合。
实习 SQL 执行安全？ 我提供的是平台执行入口。如果拦截规则不是我写的，我会说明以平台规范为准，不现场编一套网关。
代码是不是全自己手写？ Arbor 有 AI 辅助实现。分层、隔离、评测口径是我定的，我能讲到代码结构和测试。不装带人的 owner。

03-项目深挖技术面

项目深挖技术面 · Sail

依据：JD1/JD3 的记忆、上下文、工具、RAG、评测；2026-08 美团 Agent 应用一面从项目开刀，候选人自述失分在工具异常与召回排查（B 级面经，含课程推广，只用来判断题型，不当该公司流程）。

本轮目标：让面试官相信你做过一个能讲清边界的 Agent 应用，而不是会报框架名。

开场 30 秒（可接自我介绍之后）

和岗位最相关的是 Arbor。它不是聊天套壳，是数字员工的记忆和权限。我可以按「谁来用、记忆怎么分层、工具怎么调、怎么证明没串线」讲。实习是 Java 接调度和采集，用来说明我会把内部系统做成可调用接口。

本轮会用到的 bullet

高频题（对 Arbor 作答，不背通用答案）

1. 整体架构
接入（鉴权、会话）→ 应用用例（发消息、确认知识、导入）→ 领域规则（权限、冲突不能自动改档案）→ 外围（库、向量、模型、对象存储、队列）。模型只在已经授权、已经检索好的材料上生成。

2. 为什么需要 Agent，而不是固定流程？
固定流程适合「点按钮就同步一张表」。数字员工要在资料里找相关经历并决定是否调日历/工单，路径不固定。不确定的交给模型，权限、过滤、是否落库由代码决定。

3. 记忆怎么分层？
档案稳定身份；会话摘要是短期；经历目录是可导航长期结构；向量是细节。长期写入要人确认。不要把这套说成业界标准名词堆砌，说是这个产品的取舍。

4. 召回变差怎么查？
先看是否漏了工作空间过滤（这是事故）。再看身份题有没有错误地只走向量。再看经历有没有命中。最后看融合和裁窗是不是把高分细节裁掉了。我有检索元数据（命中 id、来源、子问题），没有线上监控大盘。

5. 工具失败怎么办？
不在白名单：不调用。外部接口失败：把失败结果给后续生成或直接返回错误，不假装成功。没有做成完整生产重试队列，这是缺口。

6. 为什么不用 LangChain 当底座？
隔离和记忆规则要在无网络下单测。框架适合拼链路。我了解常见抽象（工具、检索、记忆），实现选择自研应用层编排。

7. 幻觉怎么压？
引用必须属于本轮材料；生成评测只看是否超出本轮文本；隔离题若检索到禁读内容直接记泄漏，不用生成模型投票。

  • MCP、多智能体通信、CoT/ToT 论文细节
  • 生产 QPS、成本、GPU
  • 实习「自定义海豚插件」除非对方问且你真做过
